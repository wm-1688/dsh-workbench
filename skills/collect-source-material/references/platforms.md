| 平台 | 状态 | 实测数据 |

**注意**：`list` 的条目探测是「在未知结构里按小写键名找数组」。头条用 `Title` 所以能匹配；若某平台字段名不在候选表里（`title/word/query/name/note/content`），脚本会**明确报「结构未适配」并把原始响应存盘**，而不是静默返回空列表。

## 三、两个必须处理的坑

### 1. 编码

中文媒体大量使用 **GB2312 / GB18030**（实测三个新闻站全是）。默认按 UTF-8 读会得到乱码或直接抛异常。

脚本顺序：响应头 `charset` → HTML `meta charset` → `utf-8` → `gb18030` → `gbk` → `big5`。

### 2. 元数据藏在会被清洗掉的行里

「2015-10-04 13:26:00 来源：羊城晚报」这种版式行，既是元数据又必须从正文删掉。

因此：**发布时间与原始信源从原始文本抽取，正文才做清洗**。曾经因为先清洗后取时间，导致发布时间显示「未识别」。

同类坑：
- `meta author` 常是 CMS 垃圾值（实测拿到过 `midi`），必须过合理性校验
- 「来源：X 编辑：Y 校对：Z」要把编辑校对摘出去，只留信源
- 图片说明常被复读多遍（实测同一句出现 3 次），按行内句子去重

## 四、维护方法

**改适配器前先重测，不要凭记忆改。**

```bash
# 1. 看榜单接口是否还活着
python {baseDir}/scripts/fetch_material.py list toutiao --out materials

# 2. 结构变了：原始响应会存成 materials/raw-toutiao.json，读它确认字段名，
#    然后把字段名加进 _find_items() 的候选表或 HOT_LISTS 的专属配置

# 3. 正文抓空了：检查是不是变成了前端渲染或验证页
python {baseDir}/scripts/fetch_material.py fetch <url> --out materials
#    看输出的「编码 / 抽取」列和正文字数；必要时把原始 HTML 存下来人工比对
```

## 五、明确不做的事

- **不绕登录态**：不注入 cookie、不带 session、不模拟登录。
- **不破签名**：不为抖音 / 小红书实现签名算法（会持续失效，维护成本高于收益）。
- **不静默失败**：取不到就报错并给替代路径（用 `hot-topics` 取榜单，或请用户粘贴正文）。
- **不把转载当一手**：聚合站页面的「核验状态」一律标 `需要核验`，并写入原始信源。
