# 采集来源素材

把链接变成**可用的素材**，而不是把网页变成一段文字。

下游要的是事实锚点：**原话、数字、动作、时间线、当事人**。热榜标题给不了这些，报道全文才有。

## 能力披露

- **网络**：读取用户给定的 URL；`list` 子命令访问实测可用的公开榜单接口。
- **凭证**：无。不读 key、不带 cookie、不登录。
- **文件写**：只在 `--out`（默认 `materials/`）下写素材卡与榜单 JSON。
- **不做什么**：不改写、不总结成文、不判断选题价值、不发布。

## 用法

```bash
# 一个或多个链接 → 素材卡（.md 人读 + .json 机器读）
python {baseDir}/scripts/fetch_material.py fetch <url> [<url> ...] --out materials

# 直取热点榜单（实测可用：toutiao / douyin / baidu）
python {baseDir}/scripts/fetch_material.py list toutiao --out materials
```

只依赖标准库。

## 素材卡字段

| 字段 | 说明 |
|---|---|
| 标题 | 经过合理性过滤（会剔除 h1 里的 "302 Found" 这类状态页文本） |
| 来源 URL / 域名 | 采集地址 |
| 发布方 | 页面账号或站点名；与原始信源**不是一回事** |
| 原始信源 | 页面标注的「来源：X」 |
| 发布时间 | meta 优先，其次正文里的时间串 |
| 抓取时间 | 采集时刻 |
| 编码 / 抽取 | 实际用的编码与抽取策略（排障用） |
| 正文字数 | 去空白后的字数 |
| 核验状态 | **可直接判断**（一手媒体）/ **需要核验**（聚合站转载、来源不明） |
| 版式残留 | 编辑、校对等，已从正文移出但保留备查 |

## 三条硬规则

1. **核验状态必须标注，不许省略。** 聚合站（百家号、头条、搜狐、网易、新浪、凤凰）的页面**不是原始信源**。下游写作时写「有报道写」而不是把转载当一手事实。
2. **失败要明说原因和替代路径。** 403/401（微博、知乎）意味着需要登录态；返回空响应意味着接口已改版。**不要假装抓到了**，也不要反复重试同一个地址。替代方案：用 `hot-topics` 取榜单，或请用户手动粘贴正文。
3. **编码不能默认 UTF-8。** 中文媒体大量使用 GB2312/GB18030（实测央广网、中新网、中国经济网全是）。脚本已按 响应头 → meta → utf-8 → gb18030 → gbk → big5 依次探测。

## 结果怎么用

- **给写作**：把素材卡的「正文」直接作为素材喂给写作技能；引用数字与原话时回到「原始信源」确认。
- **给对标拆解**：一次 `fetch` 多篇同类文章 → 逐篇看「开头手法、段落节奏、用词」。
- **给选题**：`list` 拿榜单 → 挑出有「人物 + 动作 + 结果」的条目 → 再 `fetch` 它的报道全文。**标题不构成素材。**

## 已知边界

| 目标 | 状态 |
|---|---|
| 新闻站（央广网、中新网、人民网、澎湃等） | ✅ 实测可采 |
| 百家号 | ✅ 实测可采（服务端渲染，正文 375 字） |
| 微信公众号文章 | ⚠️ 未实测，预期可用（服务端渲染）。首次使用请先验证 |
| 今日头条 / 抖音 / 百度 榜单 | ✅ `list` 实测可用（头条 50 条） |
| B站榜单 | ❌ 接口已改版或需签名，返回空响应 |
| 微博、知乎 | ❌ 403 / 401，需登录态 |
| 小红书、抖音正文 | ⛔ 强反爬，不建议自建。请用户手动粘贴或接第三方服务 |

平台细节与维护方法见 `references/platforms.md`。

## 最终自检

- 每个素材卡都有来源 URL、抓取时间和核验状态？
- 转载页面的原始信源是否已写入「原始信源」字段？
- 失败项是否给出了原因与替代路径，而不是静默跳过？
- 是否把榜单标题当成了素材？（标题不是素材，必须补采集正文）
- 是否没有改写、没有生成观点、没有替用户判断选题价值？
